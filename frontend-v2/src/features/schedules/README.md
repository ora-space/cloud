# 定时任务

列表、筛选、开关及右侧抽屉统一管理持久配置。页面从当前租户的真实项目存储和共享执行 Catalog 读取项目、模型、执行器；没有示例项目、浏览器内模拟运行或第二份任务目录。“运行工作流”在 `schedule-resources` 列出工作流（`available.workflows`）时可选；“已有任务”在真实目录/执行入口就绪前禁用，已有持久引用配置继续可读，不用浏览器演示库冒充后端资源。

## 职责边界

工作流参数定义、类型解析、语义校验和实际执行属于工作流模块；任务来源与执行绑定属于任务模块。此页面只消费它们交付的接口，不导入工作流编辑器/mock/runtime、不提前制定参数协议。可编辑直接对话和工作流两种配置；旧的 workflow 引用（没有 `workflowId`/`snapshotId`）和 task 引用保持只读，不解析其参数或构造写请求。

工作流配置选一个已发布的工作流、必选的项目和可选的初始输入，不选模型和执行器（由工作流各节点决定）。保存时把所选工作流**当前生效的快照**写进配置，之后发布的新版本要重新保存任务才会使用；表单和详情都说明当前固定的是哪个版本。每次触发由服务端创建并启动一次独立的工作流运行（同一个触发只有一个运行），这次运行也列在对话页对应项目下。运行历史里工作流记录的结果按 occurrence 的 `executionRef`（`{"workflowRunId"}`）读工作流运行详情（`lib/workflows/api` 的生成客户端），显示运行状态和输出或失败原因，不走对话结果接口。

## 配置与资源

`GET /schedule-resources` 是定时页的只读投影，复用共享项目与 Catalog，不创建项目或保存模型凭据。响应区分目录不可用和可用但为空；页面可显式刷新，并每30秒刷新资源。失效的已选项不静默换成另一个模型、项目或执行器。切换模型/项目会清空执行器选择，保存前重新选择对应绑定。

无项目对话选择模型，不需要 Agent；有项目对话必须选择当前项目和匹配模型的执行器，保存时由后端再次校验。模型服务尚未就绪时，仅允许先保存无项目、未绑定模型的文本配置，明确说明尚不能执行。工作空间/用户变化使用独立查询键，失败时不回退示例数据。编辑遇到版本冲突保留输入并要求重新打开，避免覆盖其他操作。

时间规则支持每天、工作日、每周和固定小时间隔；日历预览按任务时区计算，间隔以创建时间为锚点。预览不证明运行已经发生，配置暂停也不取消已开始的执行。

## 操作与历史

“立即运行”消费共享操作 API，稳定 requestId 按用户/租户/任务保存在 sessionStorage；网络错误、超时或操作冲突后重试保留原键，只有收到确定回执后清除。显式下一次运行才生成新键，不因失败自动创建替代执行。取消始终使用原 occurrence ID，未确认停止时不乐观改成“已取消”。工作尚未结束时保留占位提示。

历史按接口复合游标分页，详情打开期间每3秒刷新；有执行引用的选中运行单独读取完整结果，活动运行的结果每2秒刷新。结果读取把记录版本计入查询标识：活动期间读到的“尚无最终结果”不会在占位释放后继续沿用，记录进入终态时会按新版本再读一次，避免把中间状态冻结成最终展示。刚创建的记录可能不在当前分页里，因此按返回 ID 单独读取，不拿另一条记录代替。接口与合并列表均按 `recorded_at DESC, id DESC` 时间倒序排列，同记录时间按不可变 UUID 降序兜底。列表显示已经读取的运行事实，未读取时提示查看记录；不把请求回执的“进行中”冻结为最终状态。

成功、失败、取消、中断、跳过和核对中分别展示。只有完成且 answerComplete 的答案标为“完整结果”，其他结果如实说明部分/未完成；输出用文本显示。读取失败、接口尚未安装和真正的空历史是不同状态。GET 不触发执行，刷新不自动重跑。操作提示仅确认请求已记录/处理，当前状态以持续刷新的运行事实为准。

## 契约与验证

- 配置和资源：`v2-server/schedules.openapi.json`，生成 `api/generated.ts`。
- 执行操作：`v2-server/schedule-actions.openapi.json`，生成 `api/actions/generated.ts`。
- 只读历史和完整结果：`v2-server/schedule-history.openapi.json`，生成 `api/history/generated.ts`。

后两份候选契约由各领域提供方维护，此页面只消费，不另实现调度器或公共执行服务；相应后端尚未装配时显示明确不可用。真实资源目录能读不等于操作路由已安装，不能以目录成功代替运行验收。客户端统一经 Orval 生成和现有认证请求器访问；不修改正式 `api/openapi.json`。运行 `npm run api:generate:schedules` 同时更新三份客户端。

`npm run check` 检查生成漂移、类型、lint、单元测试和构建。`npm run e2e` 使用真实 v2-server/PostgreSQL 执行真实运行：`e2e/schedule-runs.spec.ts` 通过“立即运行”触发 fixture 模型，读取成功状态、完整回答，并在刷新后确认历史仍可读。有项目 Agent 的执行与取消用例需要 `task v2:node:prepare` 准备的资源，通过 `V2_NODE_ASSETS_DIR` 和独立的 `V2_DATA_DIR` 显式提供；没有这些资源时用例自身跳过，不能算作已通过。测试替身仍只用于可控网络失败、分页和状态边界。
