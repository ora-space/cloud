# 协作

页面和导航叫「协作」（路由 `/collaboration`），承载两块真实数据：任务（task）与小队（squad）。任务是工作区里指派给人、Agent 或小队的一件活，属于一个项目，全团队可见；小队是工作区内人和 Agent 的协作编组，回答「哪些人和 Agent 一起承接哪类任务」，与工作区成员资格分开。两块数据都来自 v2-server 的候选接口。

## 已经有的

- 任务列表按最近变更排序，显示状态、标题、所属项目与指派人；空态引导建第一个任务。没有任何演示任务或虚构指派。
- 任务详情：标题、描述、项目、创建人与更新时间、指派对象、状态动作和评论占位。状态按「待处理 → 进行中 → 待验收 → 已完成」逐级推进，`已取消` 可从任一未结束状态到达；已完成与已取消不再提供动作，界面写明任务已结束。
- 创建与编辑任务选择工作区里已有的项目；任务必须属于一个项目，表单在项目加载完成前不允许提交。标题、描述长度在前端先校验，服务端再校验一次。
- 指派是单选一个类型化目标：工作区有效成员、空间里已安装的 Agent，或未归档的小队。指派给小队只表示这个队负责，界面明确写出不会自动分派给成员；指派给 Agent 时写明需要人点「开始处理」，真正启动 Agent 执行、跑完自动进入待验收尚未接入。
- 评论区先留出位置，说明评论写入、执行记录与运行详情在后续版本接入。
- 任务写操作按任务 version 做乐观校验：版本过期提示关闭后重新打开，非法迁移与服务端错误码也给出对应说明，不静默重试。
- 小队列表显示服务端返回的有效计数：人类成员数、Agent 成员数、维护者数，以及是否已设 leader。空态引导创建一个小队，不展示演示卡片。
- 详情按类型展示成员（人类 / Agent 分色）、各自职责、维护者与 leader 标记，并列出已退出的历史编组。
- 创建小队时创建者成为本队人类维护者；维护者可以编辑名称、简介与协作说明，或归档。归档需要二次确认，归档后详情只读。
- 维护者可以从「添加成员」面板加入已有工作区成员：候选只来自契约的 `tenants/{tid}/members`，已在本队的有效成员不再出现，可按姓名筛选并填写职责。移除成员需要二次确认，移除后进入「已退出」历史，界面上写明移出小队不影响工作区成员资格。
- 任何有效成员都能在自己的队员行点「退出小队」离开，不需要维护者权限，退出后同样保留历史；维护者仍可用「移除」去掉其他成员。
- 维护者可以在队员行增删其他维护者的标记，也可以把在队的 Space Agent 设为 leader 或清除 leader；不设"最后维护者"保护，退出后允许零维护者。
- 同一个面板还能加入空间里已安装的 Space Agent：候选来自契约的 `spaces/{sid}/plugins`，只列 `kind=agent` 且观测为已安装的条目，显示插件标识与版本，不虚构 Agent。加入只建立本队编组，不启动执行，也不授予运行时权限；Agent 不能是维护者。
- 写操作按小队 version 做乐观校验；版本过期、无权限或小队已归档时给出对应提示，不静默吞掉。

## 还没有的

- 多用户登录与邀请入口在本功能之外（成员页承接），小队详情只针对已经在工作区里的人进行编组。
- 任务评论、执行记录与运行详情；`@小队` 提及。
- Agent 真正执行：现在指派给 Agent 只记录归属，点「开始处理」只改状态，不会启动执行；跑完自动进入待验收属后续工作。
- 自动委派与 leader 路由。界面明确写「尚未接入」，不提供暗示可用的入口。

小队成员关系本身不授予私人模型、Git 凭据或运行时权限。

## 接口与检查

小队与任务接口都不在正式 Cloud 契约里：小队由 `v2-server/squads.openapi.json` 描述，用 `npm run api:generate:squads` 生成 `api/generated.ts`；任务由 `v2-server/tasks.openapi.json` 描述，用 `npm run api:generate:tasks` 生成 `tasks-api/generated.ts`。两个客户端分目录存放，各自的 Orval 配置会清空自己的输出目录。任务表单用的项目列表来自 `src/lib/projects-api`（聊天页与协作页共用，因此放在 `src/lib/`），由 `api:generate:chat` 生成。`npm run check` 会先做 `api:check:squads`、`api:check:tasks`、`api:check:chat`，确认生成结果没有漂移。会话与租户继续走正式生成客户端。

`npm run check` 运行类型检查、lint、单元测试和构建；`npm run e2e` 用真实 v2-server 与 PostgreSQL 跑建任务、改状态、指派、刷新，以及建队、增删成员、归档流程，并通过 `E2E_DATABASE_URL` 与 `PW_CHROMIUM_PATH` 指定数据库和浏览器。
