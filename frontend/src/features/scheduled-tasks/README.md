# 定时任务（scheduled-tasks）

本模块负责定时任务的**界面**：任务列表与表单、以及单个任务的运行历史。它不拥有任何服务端
事实：任务的接纳、verdict 与产物计数都来自 Cloud 的 REST 资源，本模块只负责请求、呈现和把
用户操作变成 mutation。

## 文件

| 文件 | 职责 |
| --- | --- |
| `api.ts` | 本模块用到的查询与 mutation 包装（列表、历史、创建、启停） |
| `scheduled-tasks-page.tsx` | 页面：列表、创建入口、打开历史 |
| `scheduled-task-form.tsx` | 创建与编辑表单 |
| `scheduled-task-history.tsx` | 运行历史对话框：每次到期点的接纳结果、verdict 与产物数量 |
| `scheduled-tasks-page.test.tsx` | 页面行为测试 |
| `scheduled-run-artifacts.tsx` | 按需展开已登记产物，提供同源附件下载链接 |
| `scheduled-run-artifacts.test.tsx` | 同源附件链接、按需列表与重试测试 |
| `scheduled-task-history.test.tsx` | 历史呈现测试（含「未报告」） |

## 依赖

- 依赖：`@/api`（生成的客户端）、`@/components/ui`、`@/lib` 下的边界适配。
- 允许被谁依赖：路由/页面组合层。

## 不变量

- **「未报告」是一个值，不是缺字段**：运行没有 verdict 时显示「未报告」，不要隐藏这一行，也
  不要把空字符串当作通过。
- **产物计数只表示已登记对象**：`artifactCount` 来自 Cloud 的索引计数，`rejectedArtifactCount`
  是被拒候选；两者不可相加，也不代表用户能否下载（下载由 Cloud 的单独接口按可见性授权）。
- **不在前端缓存服务端事实**：历史与计数只经 TanStack Query 读取，不复制进组件状态。

## 测试

历史测试通过 MSW 提供固定响应，断言渲染结果（结论文案、被拒数量）；不要 mock 内部模块。

创建入口只依据 Cloud 列表响应的 `acceptanceEnabled`；本模块不决定开关，服务端仍独立验证写入。表单可选择创建者默认连接中的模型，实际连接/凭据会在接纳时冻结到运行；不选择时使用当时默认模型。禁用创建是无授权草稿，不发送授权；已停用任务在页面上必须重新勾选风险说明后才能启用。

卡片上的"下次运行"只展示 Cloud 每次读取时现算的 `nextDueAt`，按任务时区格式化；前端不自行推算 schedule，停用任务没有该值。

产物列表只含元数据；下载链接指向 Cloud 同源路径，每次点击由服务端重新鉴权并校验文件，以安全附件返回。浏览器不取得对象存储地址、凭据或有效期，不在应用内渲染产物正文。

历史通过 `artifactsExpired` 明确显示已成功交付后被清理的产物，不把从未产生产物的运行标为过期。

保存失败只按错误码显示有界文案，不渲染服务端细节。`name_conflict` 表示创建者在同一 issue 下已有同名任务（已删除的任务仍占用名称），提示改名后重试，表单保持打开。

失败原因 `task_paused`、`task_handoff_pending` 显示为指向任务对话的说明：这两种拒绝要到任务对话里处理，不是任务或智能体配置的问题。其余失败原因保持原始代码。
