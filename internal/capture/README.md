# capture：子进程输出的有界缓冲

[中文](README.md) | [English](README.en.md)

`Buffer{Limit}` 是一个 `io.Writer`，可直接交给 `exec.Cmd`：保留前 `Limit` 字节，其余只计入 `Dropped`。Repo Executor
启动的 Git 的输出由远端决定（sideband 文本、ref 广告、诊断），无界缓冲等于把本进程的内存交给选择仓库的人。

| 方法 | 含义 |
|---|---|
| `Write` | 永远返回完整长度、永远不返回错误 |
| `Len` | 子进程一共写了多少（保留 + 丢弃） |
| `Truncated` | 是否超过上界 |
| `Bytes` | 保留的原始字节（解析前先看 `Truncated`） |
| `String` | 保留的文本，被截断时末尾附 `…(N bytes dropped)` |

不变量：

- **写入不失败**：子进程输出经 `io.Copy` 到达缓冲，短写会让复制提前结束、关闭管道，子进程因此收到 `SIGPIPE`。
  返回完整长度、丢弃装不下的部分，上界才只是本进程的内存性质，而不是子进程的新故障。
- **截断是结果的一部分**：被截断的 stdout 不作为事实采用（ADR `repo-executor/0` D4）；由调用方决定如何处置。
- 不做脱敏：明文只在调用方手里，调用方对整份捕获先脱敏再截断到报告窗口。

测试：上界内、恰好上界、单次跨越、写满后继续写、零上界，以及用 `io.Copy` 搬一份超过上界的流不报错（`SIGPIPE`
回归用例）。依赖：仅标准库。
